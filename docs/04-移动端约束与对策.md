# 04 移动端约束与对策

这一份是本项目最容易低估的部分。桌面写得好好的代码，搬到 Android 上会以完全不同的方式失败。

## 1. 约束总表

| 约束 | 后果 | 对策 |
|---|---|---|
| 无 Node.js | 没有 `fs`/`child_process`/`net`，不能用 git、rg | 全部走 `app.vault.adapter` + `requestUrl` |
| `requestUrl` 不支持流式 | 没有打字机效果，长回答要干等 | 先非流式 + 状态行；需要时改用 fetch |
| 跨域（fetch） | 部分模型端点的 `fetch` 被 CORS 拦 | 实测后再开；不行就只用 `requestUrl` |
| 后台被杀 | 长 run 中断、文件改一半 | checkpoint + 幂等工具 + 续跑提示 |
| 无 devtools | 报错看不见 | 落盘日志 `logs/agent.log` |
| 触屏 | 面板窄、键盘遮挡、误触 | 单列布局、按钮大、确认弹窗 |
| 电池限制 | 后台网络被断 | 引导用户设「无限制」 |
| 键盘/输入法 | 长文本输入困难 | 优先短指令 + 系统语音输入 |
| 同步冲突 | 多端同时改产生 `.conflict.md` | 批量改动时提示别在别的端编辑 |
| 屏幕尺寸 | 表格、diff 横向溢出 | diff 用单列行级展示 |

## 2. 流式：先不做，但留接口

`requestUrl` 会把整个响应读完才返回。所以 MVP 一律非流式。

体验补偿：工具调用期间在面板上显示状态行

```
正在调用 patch_file(读书/置身事内.md) …
已完成 3/5 个文件
```

这比空白等待好得多，而且信息量比 token 流更有用（用户关心的是「在干什么」而不是「逐字蹦出来」）。

需要流式时的路线：

1. 先用 `fetch` 直连，确认端点是否返回 `access-control-allow-origin`
2. Obsidian 桌面是 Electron，CORS 松；移动端是 WebView，严格
3. 若被拦，只能让用户自建反代（成本高，不建议给自用项目做）

**决策：v0.2 之前不碰流式。**

## 3. CORS 实测方法

在决定支持哪个端点前，跑一次：

```bash
curl -s -D - -o /dev/null https://api.deepseek.com/chat/completions \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer sk-xxx' \
  -d '{"model":"deepseek-chat","messages":[{"role":"user","content":"hi"}]}' \
  | grep -i 'access-control'
```

- 有 `access-control-allow-origin: *` → 可以用 `fetch` 流式
- 没有 → 只能 `requestUrl`

把结果填进下表（实测后更新）：

| 端点 | CORS | 可用流式 | 备注 |
|---|---|---|---|
| DeepSeek | 待测 | 待测 | 默认推荐 |
| Moonshot | 待测 | 待测 | 长上下文 |
| 智谱 | 待测 | 待测 | |

## 4. 被杀后台：三层防护

**第一层：状态落盘**
每步工具执行后写 checkpoint。粒度是「一次工具调用」，不是「一个 run」。

**第二层：工具幂等**
`patch_file` 天然幂等（第二次必然未命中而失败），`create_note` 检查已存在则报错而不是覆盖。这样即使 checkpoint 落后一步，重放也不会写坏。

**第三层：续跑不自动**
重开 App 时只提示「有未完成任务，是否继续」，绝不静默恢复。静默恢复 + 幂等不完美 = 数据损坏。

用户侧还需要一步手动设置：

```
设置 → 应用 → Obsidian → 电池 → 无限制
设置 → 应用 → Obsidian → 自启动 → 允许
```

## 5. 日志

手机上没有控制台。`util/log.ts` 需要：

- 内存环形缓冲（最近 200 条），面板里可看
- 追加写入 `<plugin>/logs/agent.log`，每天一个文件，保留 7 天
- 记录内容：时间、runId、step、工具名、耗时、错误摘要
- **不记录**：笔记全文、API Key（打码成 `sk-***abcd`）

排查流程：面板 → 「导出日志」→ 复制到聊天框 / 或直接用文件管理器取。

## 6. UI 适配

| 区域 | 桌面 | 手机 |
|---|---|---|
| 会话面板 | 右侧 sidebar | 底部抽屉 / 全屏 sheet |
| diff | 并排双栏 | **单栏**，红色删除 / 绿色新增逐行 |
| 确认按钮 | 内联小按钮 | 底部固定大按钮 |
| 输入框 | 多行 | 单行自动增高，最多 4 行 |
| 工具状态 | 折叠列表 | 一行状态 + 可展开 |

手机上的 diff 不要做并排，屏幕宽度不够，必然错位。

## 7. 同步冲突

如果 Vault 走 Syncthing / Obsidian Sync：

- 批量改动时，其他端应处于关闭状态（或至少不打开同一批文件）
- 冲突文件形如 `xxx.sync-conflict-20261020-113000-ABCDEF.md`，工具层可以顺手提供 `list_conflicts` 命令（非 MVP）
- Obsidian Sync 的版本历史是最后一道保险，但默认只保留有限时间

## 8. 电量与发热

- 避免在 run 里对全库做密集 IO（`search` 加时间预算）
- 不做后台轮询
- 不在手机上建 embedding 索引（这是明确的设计红线）
- 一次 run 的 `maxSteps` 默认 20，防止失控长跑

## 9. 版本要求

| 能力 | 最低 Obsidian |
|---|---|
| `vault.process` | 1.5 |
| `SecretStorage` | 1.11 |
| 移动端 widget（与本项目无关，但同版本区间） | 1.13/1.14 |

`manifest.json` 里设 `minAppVersion: "1.13.0"`，理由：SecretStorage 已在，且移动端较新的渲染与设置面板更稳。
