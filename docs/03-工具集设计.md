# 03 工具集设计

## 1. 设计原则

1. **正交**：一个工具只做一件事。`patch_file` 不兼任 `create`。
2. **幂等优先**：同样的参数执行两次，结果一致或明确报错。`patch_file` 第二次必然「未唯一命中」而失败，这是期望行为。
3. **副作用分级**：读 < 新建 < 替换 < 删除。前三者可以限制额度放行，删除必须每次确认。
4. **输出受控**：任何返回值都有硬上限，避免一次读取把 context 撑爆。
5. **错误可被模型理解**：错误信息写成人能看懂的一句话（也就能被模型看懂），不要只丢异常栈。

## 2. 工具清单

| 工具 | 入参 | 副作用 | 风险 | MVP |
|---|---|---|---|---|
| `read_file` | `path`, `from?`, `to?` | 无 | 低 | ✅ |
| `list_files` | `glob`, `limit?` | 无 | 低 | ✅ |
| `search` | `query`, `regex?`, `limit?` | 无 | 低 | ✅ |
| `get_links` | `path` | 无 | 低 | ✅ |
| `get_backlinks` | `path` | 无 | 低 | ✅ |
| `patch_file` | `path`, `old`, `new` | 精确替换 | 中 | ✅ |
| `create_note` | `path`, `content`, `overwrite?` | 新建 | 中 | ✅ |
| `write_file` | `path`, `content` | 整体覆盖 | **高** | ✅（需确认） |
| `open_note` | `path` | 切视图 | 低 | ✅ |
| `delete_note` | `path` | 删除 | **高** | 后置 |
| `move_note` | `from`, `to` | 移动 | **高** | 后置 |
| `run_command` | `id` | **任意** | **极高** | 默认关闭 |
| `web_read` | `url` | 外网请求 | 中 | 后置 |

`run_command` 能让模型调用任何插件的能力（包括 git、发布、同步），能力上限极高，也意味着失控风险极高。MVP 阶段**不注册**，等护栏成熟（只允许白名单 id）再开。

## 3. JSON Schema 片段

```jsonc
{
  "name": "patch_file",
  "description": "在指定笔记中做一次精确文本替换。old 必须在文件内唯一出现，否则失败。用于小改动，优先于 write_file。",
  "parameters": {
    "type": "object",
    "properties": {
      "path":  { "type": "string", "description": "相对 Vault 根目录的路径，如 读书/置身事内.md" },
      "old":   { "type": "string", "description": "要被替换的原文，必须唯一" },
      "new":   { "type": "string", "description": "替换后的文本" }
    },
    "required": ["path", "old", "new"],
    "additionalProperties": false
  }
}
```

写 description 的要点：**把使用条件和失败条件都写进去**。模型读不到你的源码，`description` 就是它的使用手册。

## 4. `patch_file` 的语义细节

这是最容易做错的工具，单独说明。

```ts
async function patchFile(ctx, { path, old, new: replacement }) {
  const file = mustGetTFile(ctx.app, path);
  let hit = 0;
  const next = await ctx.app.vault.process(file, (data) => {
    // 统一换行，避免 Windows 换行导致匹配失败
    const norm = data.replace(/\r\n/g, '\n');
    const target = old.replace(/\r\n/g, '\n');
    const parts = norm.split(target);
    hit = parts.length - 1;
    if (hit !== 1) return data;         // 不满足唯一性：原样返回
    return parts.join(replacement.replace(/\r\n/g, '\n'));
  });
  if (hit === 0) throw new Error(`未找到要替换的文本（${path}）。请先用 read_file 确认原文。`);
  if (hit > 1)  throw new Error(`目标文本出现 ${hit} 次，不唯一（${path}）。请提供更长的上下文使其唯一。`);
  return { ok: true, path, bytesChanged: next.length - (await ctx.app.vault.adapter.stat(file.path))!.size };
}
```

要点：

- **必须做换行归一化**，否则从模型那里拿到的 `\n` 和文件里的 `\r\n` 对不上，永远匹配失败
- **0 次和多次都报错**，两次报错信息不同——这直接影响模型能否自我修正
- 用 `vault.process` 而不是「读 → 改 → 写」，避免并发把别人的改动覆盖掉

## 5. `search` 的实现取舍

MVP 不引入索引，直接遍历：

```ts
async function search(ctx, { query, regex = false, limit = 20 }) {
  const re = regex ? new RegExp(query, 'gi') : null;
  const needle = query.toLowerCase();
  const out = [];
  for (const file of ctx.app.vault.getMarkdownFiles()) {
    if (out.length >= limit) break;
    const text = await ctx.app.vault.cachedRead(file);
    let idx = -1;
    if (re) idx = text.search(re);
    else idx = text.toLowerCase().indexOf(needle);
    if (idx < 0) continue;
    out.push({ path: file.path, preview: text.slice(Math.max(0, idx - 80), idx + 120) });
  }
  return { count: out.length, truncated: out.length >= limit, hits: out };
}
```

已知问题与对策：

| 问题 | 现状 | 改进 |
|---|---|---|
| 大库（>5000 篇）遍历慢 | 串行读，可能十几秒 | v0.2 加 `Promise.all` 分批并发 + 单次时间预算 |
| 无相关性排序 | 按路径顺序 | v0.2 按命中次数排序 |
| 中文分词 | 子串匹配，够用 | 不引入分词器 |

## 6. 护栏清单

所有工具执行前统一过一遍：

1. **路径规范化**：`path.posix.normalize`，去掉前后 `/`，拒绝含 `..` 的结果
2. **禁止区**：`.obsidian/`、`.git/`、`.trash/` 一律拒绝（否则模型能改插件配置、偷 API Key）
3. **扩展名**：默认只允许 `.md` / `.canvas` / `.base`；写其他类型需显式开关
4. **大小限制**：单文件读取上限 1 MB，写入上限 1 MB
5. **确认策略**：

| 工具 | 是否确认 |
|---|---|
| `read_*` / `list_*` / `search` / `get_*` / `open_note` | 否 |
| `patch_file` | 默认否，单次 run 内累计超过 5 个文件时改为逐次确认 |
| `create_note` | 否（目标不存在才创建） |
| `write_file` | **是** |
| `delete_note` / `move_note` / `run_command` | **是** |

6. **快照**：进入「批量改动」状态前，把涉及文件的原内容存一份到 `state/snapshots/<runId>/`，供回滚。

## 7. 工具返回值风格

统一结构，方便模型判断：

```jsonc
// 成功
{ "ok": true, "data": { ... } }
// 失败（会作为 tool 消息回灌）
{ "ok": false, "error": "未找到要替换的文本（读书/xx.md）。请先用 read_file 确认原文。" }
```

不要返回 HTTP 状态码式的数字，也不要返回空对象——模型对「空」的处理很差，宁可明确说「0 条命中」。
