# 07 风险与开放问题

## 1. 风险表

| # | 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| R1 | 模型不支持/不稳定支持工具调用 | 中 | 高 | 启动时自检 `tools` 能力；失败则降级为「只生成文本」模式 |
| R2 | 手机端网络对模型端点不稳定 | 中 | 高 | 优先国内直连端点；加超时与重试；必要时改电脑端 |
| R3 | 后台被杀导致文件改一半 | 高 | 高 | checkpoint + 幂等工具 + 续跑确认（见 04 文档） |

| R5 | 一次 run 烧掉大量 token | 中 | 中 | `maxSteps`、读文件行数上限、检索结果上限、run 结束显示用量 |
| R6 | API Key 泄漏 | 低 | **高** | 存 `SecretStorage`；日志打码；禁止同步插件配置到云端 |
| R7 | 模型把 `.obsidian/` 改坏 | 低 | **高** | 路径护栏硬拦截，不依赖提示词 |
| R8 | 与同步工具打架产生冲突文件 | 中 | 中 | 批量前提示；工具层可选提供 `list_conflicts` |
| R9 | 自己维护不动，项目烂尾 | 中 | 中 | 每个里程碑都要能自用；M1 不达标就止损 |
| R10 | Obsidian API 变更导致插件失效 | 低 | 中 | `minAppVersion` 锁版本；不依赖未文档化的 API |

## 2. 开放问题

### Q1 流式到底能不能做？

未验证。需要先测端点 CORS。若能，用 `fetch` + `ReadableStream`；若不能，维持非流式。
**结论产出物**：一张「端点 × CORS × 可流式」的表，填进 04 文档。

### Q2 要不要做向量检索？

当前判断：**MVP 不做**，理由见 05 文档。但需要验证一个假设——「关键词检索 + 记忆文件」是否足够支撑场景 B（跨文件合成）。

验证方法：M1 完成后，连续两周只用关键词检索做周报合成，记录「找不到相关笔记」的次数。若每周 > 2 次，考虑 M3 的局部索引。

### Q3 记忆文件该多大？

Mobie CC 强调 bounded 但没给数字。建议每类 ≤ 8 KB（约 2000 汉字），超了就要求模型压缩重写。需要实测：8 KB 的记忆对行为的影响是否可感知。

### Q4 多 Vault 怎么办？

Obsidian 插件是按 Vault 加载的，天然只作用于当前 Vault。不需要额外设计——但要确认 `state/` 也落在各自的 Vault 内，不要写到全局位置。

### Q5 要不要支持非 Markdown 文件？

`.canvas` 是 JSON，`.base` 是 YAML 类。MVP 只读不写。写入格式错误的代价太高（Obsidian 会拒绝渲染），等有真实需求再说。

### Q6 模型切换时历史消息怎么办？

不同模型的 tool_call 格式可能有细微差异。MVP 策略：切换模型时提示「新开会话」，避免格式污染历史。

### Q7 `run_command` 要不要开？

不开。它等于把整个插件生态的执行权交给模型。若将来要开，必须：白名单 id、每次确认、禁止参数化命令。

## 3. 待验证实验清单

| 实验 | 方法 | 预期 | 结论 |
|---|---|---|---|
| E1 端点 CORS | `curl -D -` 看响应头 | DeepSeek 可能不带 | **不适用**：请求走 `requestUrl`（原生层），不经过浏览器 CORS。真机实测 DeepSeek 与 mimo 端点均可通 |
| E2 手机端请求耗时 | 记录 `provider.chat` 的 RTT | 2～8 秒可接受 | **部分验证**（2026-11-12，mimo-v2.6-flash，589 篇库）：两轮实测 RTT 分别 ≈11 秒和 2～3 秒，方差大（疑似网络/负载波动）；流式生成约 36 token/s；后续调用缓存命中爬升（4928→5312→5568），计费 prompt 大头在缓存里。日志已补每次调用的耗时字段，后续可直接统计 |
| E3 杀后台时机 | 改文件过程中锁屏 30 分钟 | checkpoint 完整 | 待测 |
| E4 patch 失败率 | 统计 100 次调用的失败次数 | < 15% | **首例成功**（2026-11-12）：真机 `patch_file` 给 frontmatter tags 加 `#review`，一次命中（exact），1/1；样本量远不够统计，继续随真实使用累计 |
| E5 全库 search 耗时 | 3000 篇库上跑一次 | < 3 秒 | **部分验证**（2026-11-12）：真机库 589 篇，自检 search/语义检索全部命中且无超时；3000 篇规模仍未测 |
| E6 `vault.process` 在移动端行为 | 编辑器打开同一文件时改 | 不覆盖用户输入 | **部分缓解**：并发保护已做（`vault.process` 内二次校验唯一性，不满足则放弃并提示重读），编辑器同开的场景未真机测过 |
| E7 SecretStorage 可用性 | 存/读/重启后读 | 正常 | **间接验证**（2026-11-12）：真机 data.json 中 apiKey 为空，但存在 10-28 的真实对话历史 → Key 存在 SecretStorage 且读取成功，降级路径未触发 |

每完成一个实验，把结论写回对应文档，不要留在脑子里。

同日读路径真机验证 ✓：「搜索所有提到 #Android 的笔记」→ 模型正确选 `search_by_tag`（limit 100），2 步完成，产出 67 篇路径清单，无工具失败。写路径真机验证 ✓：「给 Android-adb命令.md 的 tags 加 #review」→ read → patch（exact 命中）→ 收尾，3 步 14 秒，目标文件 frontmatter 确认已变，`AI/03-修改记录.md` 由插件自动记入。注意：单文件改动低于 confirmAfterFiles=5，本次**没走 diff 弹窗**——弹窗路径要么凑 5 个以上文件，要么改受守卫保护的文件才触发，尚未真机验证。
