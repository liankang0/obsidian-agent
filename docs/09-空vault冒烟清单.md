# 空 vault 冒烟清单（Doc2-WP3 完成定义）

在**全新的空库**（没有任何 `AI/` 目录）里安装插件后，按下面六步走一遍。
每一步都要同时满足「功能符合预期」和「日志干净」——
`.obsidian/plugins/local-vault-agent/logs/` 里不允许出现
「找不到 AI/03」「写修改记录失败」这类报错（WP3 的核心验收就是没有噪音）。

> 与单测的关系：test/wp3.test.ts 用 MockApp 钉住了同样的行为，
> 这份清单是真机上的对应物，两者共用同一批断言口径。

## 六步

### 1. 安装并打开设置页
- 插件正常加载，面板能打开。
- 设置页「AI 工作区」区的状态行显示：
  `未检测到 AI/ 目录，AI 工作区未启用：不注入记忆块、不写修改记录、不提醒 Step 4`。

### 2. 跑一个只读任务
- 发「列一下根目录的文件」之类，正常返回结果。
- 库里**没有**长出 `AI/` 目录；日志无任何「找不到 / 写失败」报错。

### 3. 跑一个写任务
- 发「创建笔记 试验.md，内容写 hello」，文件创建成功。
- 仍然没有 `AI/` 目录、没有 `AI/03-修改记录.md`；
- 面板/日志里**没有**「改了 N 个文件，但没回写 04/05（准则 Step 4）」提醒。

### 4. 让模型记一条记忆
- 发「把刚才做的记到记忆里」，模型调用 `record_memory`。
- 工具返回 `written: false` 加一句「AI 工作区未启用……已跳过」的说明——
  是明确的跳过，不是报错；依旧没有 `AI/` 目录。

### 5. 启用工作区，复查行为恢复
- 二选一：
  a) 手动在库里建一个 `AI/` 空文件夹（留空设置，自动探测）；
  b) 在设置里把「AI 工作区目录」填成一个**已存在**的目录。
- 状态行变为 `✓ …已启用`；再跑一次写任务：
  修改记录写进对应目录、Step 4 提醒恢复、`record_memory` 正常写入。

### 6. 热生效与重启一致性
- 不重载插件，直接改设置（换目录 / 改回留空），下一个任务立即按新设置走。
- 重启 Obsidian 后重复步骤 2-3，行为与重启前一致（设置持久化）。

## 附加检查（改过设置项时）

- **指定的目录不存在**：状态行显示 `⚠ …在库里不存在，AI 工作区未启用`，
  日志有一条点名目录的 warn；插件**不会**替你创建该目录。
- **额外保护路径**：填一个现有文件名，让模型改它 → 先弹受保护确认，拒绝后文件原样。
- **额外 skill 目录**：把一个含 `SKILL.md` 的目录填进去 → 对话里模型能用 `use_skill` 读到它。
